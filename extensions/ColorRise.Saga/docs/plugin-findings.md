# Plugin model findings

What ColorRise.Saga met in Stride's plugin model (engine and cross-platform Game Studio) while being built as a third party.
A finding that blocks a feature leaves the feature out rather than changing Stride; Nicolas decides what goes upstream.

| # | Finding | What Saga tried | What happened | Workaround in Saga | Suggested change |
|---|---|---|---|---|---|
| 1 | A companion project with no `.sdpkg` of its own is packed with the engine's version in its `.sdpkg` | Packed `ColorRise.Saga.Editor` (0.1.0) and `.Editor.Avalonia` without an `.sdpkg` next to the project | The `.nupkg` is 0.1.0 and the runtime records the companions at 0.1.0, but the generated `stride/*.sdpkg` says `Meta.Version: 4.5.3-dev` (and adds `AssetFolders: Assets`) | Each companion project has its own `.sdpkg` with the right version | `PackAssets` could take the package's `$(PackageVersion)` when it makes the `.sdpkg` of a project that has none. Whether a host reads that version was not checked. |
| 2 | Against a local engine build, the extension builds only in the configuration the engine was built in | `dotnet pack` (Release by default) of the runtime, after a Debug engine build | `Stride AssetCompiler could not be found (.../bin/Release/net10.0/Stride.AssetCompiler.dll)`: the asset compiler's targets look for the compiler in the project's `$(Configuration)`, while the dev package stubs know the engine's configuration (`$(StrideDevConfiguration)`) and take every assembly from it | `Directory.Build.targets` sets `StrideCompileAssetCommand` from `$(StrideDevConfiguration)` in dev-redirect builds, so the extension builds and packs in any configuration | `_StridePrepareAssetCompiler` could use `$(StrideDevConfiguration)` when it is set, as the stubs' references do. Dev workflow only; real packages are not affected. |
| 3 | On Linux and macOS, a plain project that references Stride packages gets the Windows platform and Direct3D11 | Ran the xunit tests of `ColorRise.Saga` (a class library and a test project referencing `Stride.Engine`, no RuntimeIdentifier) on Linux against a Linux engine build | Every test failed in a module initializer: `FileNotFoundException: Vortice.Vulkan 3.0.3.0`. `Stride.Core.targets` falls back to `StridePlatform` Windows when there is no RuntimeIdentifier, `Stride.Graphics.targets` then picks Direct3D11 and strips Vortice.Vulkan, but the engine built on Linux only has the Vulkan `Stride.Graphics` | `Directory.Build.props` sets `StrideGraphicsApi` to Vulkan when the host is not Windows and nothing set it | The fallback platform could follow the host OS (`$([MSBuild]::IsOSPlatform(...))`) rather than always Windows. With published packages (which carry Direct3D11) tests that never draw would probably pass, so this mostly bites people building against their own engine build. |
| 4 | Content that only a plugin asset references is not compiled unless the plugin's compiler says where to look, and the failure names neither asset | The story asset holds its dialogues as content references (`List<DialogueDefinition>` on scenario and quest cards); the dialogues are not root assets | The asset build reported every step successful, then the bundle packer stopped with `InvalidOperationException: Could not find asset /SagaSandbox/Dialogues/Guards for bundle default`: the dialogues were never scheduled. `BuildAssetNode` collects references only inside the types a compiler returns from `GetRuntimeTypes` (the entity compilers return `Entity`) or the types it declares as `Runtime` inputs, and `AssetCompilerBase` returns none | `StoryAssetCompiler.GetRuntimeTypes` returns the scenario and quest cards (pinned by `AssetCompilationTests`) | The bundle packer could say which compiled content holds the missing reference and point at `GetRuntimeTypes`, or the dependency analysis could warn when compiled content references an asset nothing compiles. The plugin sample's compiler could also show `GetRuntimeTypes`. |
| 5 | A third party has no editor test kit: testing editor view models means copying Stride's test fixtures | Tested the story and dialogue editors (`ColorRise.Saga.Editor.Tests`) the way Stride tests the graphics compositor editor | Stride's session fixtures, fake services and dispatcher live in its test projects and are not packaged. Everything they use is public, so `SagaSessionFixture` (about 250 lines: an exclusive dispatcher, a not-supported proxy for the dialog and clipboard services, a main view model, a plugin host, the package writer and loader) does the job. Two traps on the way: Roslyn's workspace packages, which the editor packages bring, put `Microsoft.Build.Framework` in the test output, and opening a session then fails with `TypeLoadException ... DisposableWriteLock` until the test project excludes its runtime as Stride's own projects do; and the session opens an asset editor only when a view is registered for it, so a test of "open this asset" needs a stand-in view | `SagaSessionFixture` and `ExcludeAssets="runtime"` on `Microsoft.Build.Framework` in the test project | Package the session fixture and fakes (a `Stride.Editor.Testing` package), or at least ship `Microsoft.Build.Framework` with `PrivateAssets` from the packages that bring it. |
| 6 | The node graph control neither saves node positions nor says when the user moved nodes | The story and dialogue editors keep each card's position in the asset and show the cards in Stride's `NodeGraphControl` with `AutoLayout` off | The control places nodes with `SetNodePosition` and reads them with `GetNodePosition`, but a drag ends inside its own pointer handling (which marks the event handled) with no event, and a reset of `Nodes` drops every position | `SagaGraphBinding` sets the positions from the cards after the control has followed a change of the nodes, and saves the moved ones (`MoveNodes`, one undo step) from a `PointerReleased` handler registered with `handledEventsToo` and from `PointerCaptureLost` | A `NodesMoved` event (the nodes and their old and new positions) after a drag, and a `Position` that a node template can bind (`NodeGraphNode.Position` two-way), would let an editor save positions without listening to the pointer. |
| 7 | On Linux, the companion restore of the asset compiler and Game Studio cannot check the signatures of nuget.org packages | A game outside the extension's folder referencing the packed `ColorRise.Saga` 0.1.0, with the Saga and Stride feeds in its `nuget.config`, built with `dotnet build` | The game's own restore passes, then the asset compiler fails: `Could not restore package [ColorRise.Saga.Assets] version [0.1.0] ... unresolved []`, followed by `Package 'System.Threading 4.3.0' from source 'https://api.nuget.org/v3/index.json': The repository primary signature's signing certificate is not trusted by the trust provider` for a dozen old packages. The host's restore (`NugetStore`) does not prune the packages the framework provides, so it downloads them, and outside the SDK NuGet has no code-signing roots on Linux (the SDK brings its own, `trustedroots/codesignctl.pem`). Once those packages are in the NuGet cache, the build and Game Studio take the Saga packages from the feed (the story editor opens) | README: restore the three companions once through the SDK (a throwaway project with `RestoreEnablePackagePruning` false) | `NugetStore` could prune the framework's packages as the SDK does, or load the SDK's trusted roots (`X509TrustStore`) when it runs on Linux or macOS. Not checked on Windows, where the system store has the roots. |
| 8 | A game that references a plugin's runtime project gets its companions only if their projects are in the solution, and the error speaks of packages | Opened in Game Studio the sandbox solution with its three game projects only; the game references the runtime project, which declares its companions with `StrideCompanionProject` | `Editor package [ColorRise.Saga.Editor] version [0.1.0], declared by [ColorRise.Saga], was not found; assets of that package cannot be compiled or edited.` after a NuGet error, then 24 asset errors: every Saga asset fails to load. The session knows the companion's project (`CompanionPackage.Project`) but looks for a package | The sandbox solution lists the four Saga projects | Load a companion from its project when the declaring package comes from a project, or at least name the project in the error and say to add it to the solution. |
| 9 | A double click on a node of the node graph control comes from the graph, not from the node | The story editor opens the act, scenario or dialogue of a node on a double click (`DoubleTapped` on the graph, the node found from the event's source) | Nothing opened in Game Studio: the graph captures the pointer when a node is pressed (to drag it), so the second press, and the `DoubleTapped` raised from it, has the graph as its source | `SagaGraphBinding` finds the node under the pointer (`InputHitTest` at the event's position) | A `NodeDoubleClicked` event or a command on the graph (the node it was on), as for `LinkCommand`, would spare every editor the hit test. |
| 10 | Game Studio offers to reload a plugin of the solution when a `.cs` file changes, not a view | Changed the breadcrumb styles in `StoryEditorView.axaml` while Game Studio had the sandbox open | The reload button stayed off: `GameCodeWatcher` counts only `.cs` files and project files. A change of a `.cs` file of the same plugin offered the reload, which rebuilt the plugin and opened the project again in a new editor; File > Reload project also rebuilds the plugins | Touch a `.cs` file or use File > Reload project | Count `.axaml` (and the other files a build compiles, such as resources) of the projects the editor loads. |
| 11 | A command of the entity tree gets the entities from the context menu, but the asset view's selection from the palette | "Open dialogue" is placed on the entity tree's context menu and enabled when the selection is one entity with a character component | In Game Studio the palette listed it but kept it disabled with the Foreman selected in the scene: the palette's context (`CommandContext.ForPalette`) holds the selection of the asset view, and the scene editor it was opened from in `Editor`. Stride's own scene commands read `context.Editor`, which a plugin learns only from their code | `SagaCommands` takes the entity from the selection, or else from the selection of the entity hierarchy editor in `context.Editor` (pinned by `OpenDialogueIsEnabledOnACharacterOfTheEntityTreeAndOfThePalette`) | The palette could give the selection of the editor it was opened from when that editor has one, or the documentation of `CommandContext.Selection` could say what each location puts there. |
| 12 | The services a plugin adds are on the session's context, apart from the other registries | The design planned the story player on `context.Panels`, `context.ViewTypes`, `context.Services` and `CreateInstance`, and looked for `Services` on `IEditorPluginContext` next to `Panels`, `ViewTypes` and `Commands` | It is not there, and Saga first concluded it did not exist: it is on `ISessionPluginContext`, which `InitializeSession` receives. Version 1 needed no service of its own. Version 2 registers one there (`SagaPlaybackService`, the story played in the session, which the player, the timeline and the editors share), with `context.OnClose` to dispose it: it works when the session opens with Saga, since Game Studio initializes the plugins before it opens the session's panels and editors (a plugin that joins an open session is finding 19) | None needed | `IEditorPluginContext` could say in its documentation where services go, or the plugin sample could register one. |
| 13 | A node of the node graph control can't have a context menu of its own | The dialogue editor wanted "Add way out" and "Set as entry" on a right click of a node | A right press on the graph starts a pending pan and captures the pointer, and its release opens the graph's own context menu, wherever it was | The actions are toolbar buttons that act on the selected node | A `NodeContextMenu` on the control, or the release opening the context menu of the node under the pointer when it has one. |
| 14 | A plugin has no toolkit-neutral way to let the user pick from a list | "Open dialogue" on a character with several dialogues asks which one to open | The dialog services offer message boxes and pickers of the editor's own things (files, folders, packages, templates), not a list of the plugin's items | A message box with a button per dialogue (the highest priority first and by default), which suits a few dialogues, not dozens | A pick-from-a-list dialog in the dialog service. |
| 15 | The property grid builds its nodes on another thread, so an editor must not update its selection while the asset changes | The story and dialogue editors show the selected cards in the property grid and rebuild their graph whenever the asset changes | `DeletingANodeClearsTheWaysThatLedToIt` failed now and then: the grid was building the nodes of a card while the deletion changed it. An undo that removes a selected card also left the grid showing that card, since the editor had held back the update | The editors update the grid once the change, undo or redo is over (the undo service's `Done`, `Undone` and `Redone`), never while it runs | `GenerateSelectionPropertiesAsync` could wait for the current transaction or undo to end before reading the asset, or its documentation could say when an editor may call it. |
| 16 | A plugin's session services exist in an editor test only if the test initializes the plugins for the session | Tested the story timeline panel and the editors' play marks, which take `SagaPlaybackService` from the session's services | Saga's `SagaSessionFixture` (finding 5) opened the session without calling `InitializeSession`, so the service was missing. Stride's `AssetsSessionFixture` calls it; the editor test kit of the engine's plugin follow-ups has it as an option (`StrideEditorTestSessionOptions.InitializeSession`), off by default, so a test of an extension's editor that forgets it meets the same missing service | `SagaSessionFixture` calls the plugin host's `InitializeSession` after opening the session, as Game Studio does | The kit could initialize the plugins it is given by default, since an extension's editors usually rely on what its plugin registers for the session, and let a test turn it off. |
| 17 | A panel's `PanelId` constant hides `PanelViewModel.PanelId` | Gave the story player and the timeline panels a `public const string PanelId`, as Stride's `CurveEditorPanelViewModel` and the panel tests do | Warning CS0108 on each: `PanelViewModel` has an instance property `PanelId` (the descriptor's id). The two always hold the same value, so nothing breaks, but every panel that follows the convention gets the warning, Stride's curve editor included | `public new const string PanelId` | Rename one of them, for example the property to `Id`, or the convention's constant to `Id` in the descriptor's class. |
| 18 | The cross-platform Game Studio has no documented theme keys, and `ControlBackgroundBrush` is a key of the WPF themes only | The timeline control takes its background from the theme: Saga first used `ControlBackgroundBrush`, which Stride's own `DefaultPropertyTemplateProviders.axaml` uses | The resource is not found in the Avalonia Game Studio, so the background stayed unset; the header, drawn on it, came out black on the light theme, and the labels unreadable. Stride's three uses in `DefaultPropertyTemplateProviders.axaml` have the same problem (no background) | `SystemControlBackgroundAltHighBrush`, the Fluent key that Stride's command palette and error panes use; the labels take the inherited text color (`TextElement.Foreground`) | A short list of the theme keys an extension may use (backgrounds, text, borders, accents), or editor keys of its own defined for each theme; and the three uses of `ControlBackgroundBrush` replaced. |
| 19 | The panels of a plugin that joins an open session are made before the plugin initializes the session | Read the plugin host's order for a Saga package added to an open project (found by the review, not run in Game Studio) | `EditorPluginHost` calls the plugin's `Initialize`, whose panels the dock service makes at once (their view models included), and only then `InitializeSession`, where Saga registers its playback service. The panels' constructors asked the session for that service, threw, and the host turned both panels off for the session | The panels and the plugin take the service from `SagaPlaybackService.Of(session)`, made on first use; the plugin still registers it in `context.Services` for the editors (pinned by `PanelsMadeBeforeTheServiceIsRegisteredFollowIt`) | Initialize a joining plugin for the session before its panels are made, or make the panels lazily, when first shown. |

## By plugin point

Each plugin point of the design's table (section 9) and what it met.

| Plugin point exercised | Findings |
|---|---|
| Runtime package with companions, `[GameSystem]`, component with icon, content by URL | 1, 3, 4, 7, 8. The game system, the component and its icon: none met. |
| `Assets` companion: assets, compilers, templates, asset references, build errors | 4. Templates, asset references and build errors (with the asset, card and position of each mistake): none met. |
| Neutral `Editor` + `.Avalonia` companion, toolkit detection, version check | 1, 8. Toolkit detection and version check: none met. |
| Asset editors with views of a third party, public controls reused | 5, 6, 9, 13, 15 |
| `context.Panels`, `context.ViewTypes`, `context.Services`, `CreateInstance` | 12, 16, 17, 18, 19. Two panels, their views, `CreateInstance` and a session service shared by panels and editors: none met beyond those. |
| `context.Commands`, context menus of the asset view and the entity tree, palette | 11, 14 |
| Compiling and reloading editor packages from the game's solution | 8, 10 |
| Opting in to the experimental areas (`STREXP001`, `003`, `006`, `010`) | None met: the node graph controls became `STREXP010` in the engine's follow-ups to the review of stacks 7 to 9, and the build error named the id to add. |

The WPF Game Studio, which gets no Saga views, was not checked.
