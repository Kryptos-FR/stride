# Game Studio check of step 2

The list of Task 17 of `plan-step2.md`, gone through by hand in the cross-platform Game Studio (`Stride.GameStudio.Avalonia.Desktop`, Debug, built from this checkout), on Linux under Xvfb (1600 by 1000) with the Lavapipe driver, over the check game `tests/StudioCheck` (see its README). The pointer and the keys were driven with `xdotool`. Each line says "seen", "not as planned: ..." or "could not be checked: ...". The pictures are in `/mnt/project-files/tilemap/step2/`, named `studio-NN-*.png` after the number of the line.

1. **The plugin loads.** Seen. *View > Plugins* lists `ColorRise.Tessera.Editor` and `ColorRise.Tessera.Editor.Avalonia` (0.1.0-dev, "Project of the solution") under "Plugins of the project", both on. The Output panel, with debug messages on, has no line at all, so no error about Tessera. (`studio-01-plugins.png`)
2. **Add asset.** Seen. The group `Sprite` has `Tile map` and `Tile set`, each with its icon and description, after `2D sprites` and `UI sprites`. Each makes an asset with the default name (`TileSet`, `TileMap`), and the map's property grid shows one layer, `Ground`. (`studio-02-add-asset.png`, `studio-02-assets.png`)
3. **The tile set editor.** Seen, with one thing not as planned. The editor opens on a double click. `+ Image` opens the system's file dialog; with `town.png` the grid bar shows the name `town`, the tile size 16 by 16, margin and spacing 0, "4 × 2 tiles", and `Add` makes the source. The sprite sheet `Props` dragged from the asset view onto the canvas adds a sheet source with its two sprites. Not as planned: a drop on the list of sources does nothing; only the canvas takes it (the plan does not say where; the tool tip of the canvas does). Also not as planned: after a change of the selected source, the zoom is the one that fits the source selected before (town shows at 1600%, which is too wide, after Props; Props shows at 1200% after town): fixed in step 3 of this task, and seen after the fix: Props shows at 1600% and town at 1200%, each whole, whatever the source shown before (`studio-03-props-fitted.png`, `studio-03-town-fitted.png`). An image file dragged from a file manager cannot be done under Xvfb, which has no file manager. (`studio-03-grid-bar.png`, `studio-03-image-source.png`, `studio-03-sheet-source.png`)
4. **Tile data.** Seen. A click on a tile shows `Tile 1:0,0` in the property grid with `Collision`, `Kind` and `Properties`; `Kind` takes "grass", and a property `speed` added with `+`, given the type `Float` from the list (None, Bool, Int, Float, String, Color) and the value 1.5. In `Solid` mode a press hatches the tile. *Edit > Undo* takes the hatching off and *Edit > Redo* puts it back. The edit history names the steps `Add image`, `Add sprite sheet` and `Tile data`. (`studio-04-solid.png`, `studio-04-undo-redo.png`, `studio-04-history.png`)
5. **The map editor.** Seen. The editor opens on a double click, at 200% with the grid, the layer `Ground` and an empty tile set list. `+` beside the tile sets opens the asset picker, which offers `TileSet`; once added, the palette shows the source `town`. A tile picked in the palette is stamped by a click and by a drag, and its ghost follows the pointer. With the canvas focused, P, F, E, I, R and B turn on Rectangle, Fill, Erase, Pick, Select and Stamp; X and Y flip the stamp, Z turns it clockwise and Shift+Z back (the door tile, whose keyhole is off centre, painted after each key). Typing "Bridge" as the layer's name after a double click leaves the tool on Stamp, and Enter renames the layer. (`studio-05-map-editor.png`, `studio-05-keys.png`, `studio-05-flips.png`, `studio-05-rename.png`)
6. **Shortcuts and the command palette.** Seen. In *Edit > Keyboard shortcuts...*, a search for "stamp" lists the five Tessera commands with "stamp" in their title; `Stamp tool` takes Ctrl+1 (shown as "Ctrl+D1", Game Studio's name of the key), and after *Save and close*, Ctrl+1 in the map editor turns the Stamp tool on from Fill. The command palette (Ctrl+Shift+P) lists the Tessera commands under "Tessera:", the tile set ones greyed while the map editor is the active one. (`studio-06-shortcut-page.png`, `studio-06-shortcut.png`, `studio-06-palette.png`)

8. **The compositor editor.** Seen, with one thing not as planned. *Add package features* adds `TileRenderFeature` at the end of the render features, with one selector, "Tile maps in the transparent stage", on the stage `Transparent`. The sort mode of `Transparent` offers "Back to front along an axis" after Stride's three, and takes it with the axis (0, 0, 1). Not as planned: the property grid of the feature also shows `Render Data`, `Render Objects`, `Object Node References` and `Render Nodes`, and the saved compositor has them (`RenderData: {}`, `RenderObjects: {}` and so on): the `[DataContract]` of `TileRenderFeature` gives it every public member, where Stride's base class gives none unless marked. Because `Enabled`'s setter throws, the scene view of a game whose compositor was saved this way draws nothing once the scene is opened again. Fixed in step 3 of this task: the feature now saves only its selectors, and after the fix the scene view draws again. (`studio-08-feature.png`, `studio-08-sort-mode.png`)
9. **The scene editor.** Seen. *Create entity > 2D > Tile map* makes an entity `Tile map` with the component, and the asset `TileMap` dropped in the scene makes an entity `TileMap` with the map set. The map is drawn in the scene view, flips included (`studio-09-create-entity.png`, `studio-09-map-drawn.png`). The order: a second layer, `Layer 1`, above `Bridge`, has a roof tile over one grass cell; the sprite `Hero` stands at z -0.24, between the two layers (-0.289 and -0.189), half over the roof's cell and half over the next grass cell. With the camera turned toward it and the sort mode "Back to front along an axis" (0, 0, 1), the roof covers the left half of the tree and the tree covers the grass (`studio-09-axis-sort.png`). With `BackToFrontSortMode`, the tree is not seen at all: the grass is drawn over it (`studio-09-back-to-front.png`). The check game keeps the axis sort mode.
10. **R5, a change of the map in the open scene.** Seen. With the scene open, the roof tile stamped in the map editor, then a save: the scene view shows the roof at once, without closing the scene (`studio-10-scene-update.png`).
11. **R7, a click on the map in the scene view.** Seen. A click on a grass tile selects the entity `TileMap`; a click on the right half of the tree, where `Layer 1` has an empty cell in front of it, selects `Hero`; a click on the roof, which is in front of the tree's left half, selects `TileMap` (`studio-11-tile-click.png`, `studio-11-empty-cell.png`).
12. **The game.** Seen, with one thing not as planned. The camera was moved to (6, 9, 10) to look at the painted cells. Not as planned: the first build of the head project failed while making the bundles, "Could not find content [/StudioCheck/Sprites/Props], referenced by [/StudioCheck/MainScene], for bundle default: nothing compiled it". The sheet `Props` is used by the tile set and by the sprite of `Hero`, and the build reached it through the tile set first, which only reads it as an asset (row 14 of `plugin-findings.md`). Fixed in step 3 of this task: the tile set's compiler has the sheets compiled too. After the fix, `dotnet run` of `StudioCheck.Linux` under Xvfb (Lavapipe) opens the game, which draws the grass row, the roof over the left half of the tree, the tree over the grass and the water, as the scene view does, with no error in its log (`studio-12-game.png`).
13. **The WPF Game Studio.** Could not be checked: it runs only on Windows, and this check ran on Linux. Without the Avalonia package's plugin, Tessera has no views there, as the design says, so what the neutral editor gives in the WPF Game Studio (the assets, their property grids, the scene's component) remains unchecked.
